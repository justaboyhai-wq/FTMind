一、政策资料循环

采集器不把 881 份政策 ID 写死，而是在每次运行时重新检查官网入口，优先跟随官网真实资源关系。

宝安官网入口 HTML 与静态脚本
→
发现资源zcfg.js、详情 JSON
→
下载证据原文、附件、标签、来源 URL
→
Raw Package快照、哈希、关系与审计
→
RSS 同步只读 Feed + 增量指纹

采集器支持全量、增量、失败重试和定时任务。调度采用 Asia/Shanghai 时区，并跳过重叠执行；每份政策的原文、详情 JSON、附件和官方关系都留在 Raw Package 中，方便后续复核，而不是只留下模型加工后的文本。

go run ./cmd/baoan-policy-collector collect --incremental --data-dir ./baoan-policy-data go run ./cmd/baoan-policy-collector export-raw --data-dir ./baoan-policy-data --output-dir ./raw-export go run ./cmd/baoan-policy-collector daemon --data-dir ./baoan-policy-data --incremental-cron "0 2 * * *" go run ./cmd/baoan-policy-collector verify --all --data-dir ./baoan-policy-data go run ./cmd/baoan-policy-collector serve-rss --data-dir ./baoan-policy-data --addr :18320

RSS 网关只读展示每个政策包的 latest.json。下一次增量采集完成后，下一次 RSS 同步会自然看到最新内容，采集与知识库同步因此解耦。

二、Wiki 解析规则

政策 Wiki 的关键不是“让模型自由总结”，而是让不同来源、不同可信度的内容各归其位。

官方事实 · official

标题、文号、发文机构、日期、服务对象、主题、文件载体、附件和官网关系，原样保留来源和证据。模型不得补写缺失字段，也不能覆盖官网标签。

规则计算 · computed

例如“当前是否可申报”，由官方申报标识与申报起止日期共同计算，并记录计算时间、算法版本、输入证据与冲突信息。

模型分析 · derived_ai

适用行业、办理条件、所需材料、办理流程和风险提示可以由模型提出，但必须附带证据、模型、提示词版本、置信度和人工审核状态。

可追溯操作

Wiki 更新、替代、失效、回滚和质量问题写入操作日志；历史事实不被静默覆盖，答案可以回到原文和附件定位。

产品原则：官网标签是权威维度，模型只负责增加“官网没有的新分析维度”。两者在数据结构上分开，才能支持政策更新和冲突审计。

三、问答与用户信号

问答先检索政策原文、附件和 Wiki 页面，再生成带来源的回答。高风险字段（日期、金额、资格、材料和办理方式）必须回到原始证据核验。

收藏

用户把值得复用的资源或内容收藏起来，形成个人和空间内的价值信号。当前收藏服务是用户级、空间隔离的轻量记录，不会未经审核自动改写知识库。

错误反馈

用户可针对一次最终回答提交问题类型、说明、正确建议和错误片段。系统冻结问题、答案、引用、模型、智能体、渠道和知识库快照。

闭环边界：收藏和反馈都可以成为“知识优化候选”，但只有管理员确认后，才会进入重新采集、重解析、Wiki 修复、检索调整或提示词优化。

四、管理员审核与修复

反馈不是一键改知识，而是一张带审计时间线的工单。管理员从问题成立性开始判断，再决定修复哪一层。

待处理收到用户反馈
→
审核中还原回答证据
→
定位根因资料、解析、检索、Wiki、提示词或模型
→
修复复测用原问题隔离验证
→
已解决/驳回公开结论与回归样例

反馈状态包括 pending、reviewing、needs_info、fixing、resolved 和 dismissed。管理员标记已解决时，必须填写根因、处理方式和用户可见说明；用户还可以在规定窗口内补充信息或重新打开。

根因可落到原始资料或附件、解析/分块/索引、检索或重排、Wiki 内容、智能体提示词、模型生成、政策已更新、用户条件不足或非系统问题。修复后的原问题在隔离请求中复测，前后答案和引用继续留在时间线里。

五、共享空间与权限

共享空间是跨空间协作的载体，不改变知识库或智能体的原始归属。一次跨空间使用需要同时通过成员角色和资源共享权限。

层级产品含义控制范围
空间资源的归属单位知识库、智能体和成员关系
共享空间协作关系的容器谁能看到哪些共享资源
成员角色管理员 / 编辑者 / 只读空间设置、成员管理和操作上限
共享权限知识库只读 / 可写；智能体只读使用单个资源在该共享空间中的能力

最终权限取两者交集：成员是只读时，即使知识库共享为可写也不能编辑；不同共享空间可以对同一知识库配置不同权限，互不影响。

六、两个相互咬合的循环

FTMind 的持续生长来自“内容更新”和“质量治理”两条循环，而不是让模型无边界地改写政策。

内容循环

官网更新 → 定时采集 → RSS 增量同步 → Wiki/索引更新 → 政策问答
每一步都保留来源、快照和时间，新的官网状态可以替代旧的有效性判断，但不会抹掉历史证据。

质量循环

问答使用 → 收藏/错误反馈 → 管理员审核 → 修复复测 → 回归样例 → 知识再优化
人工确认是知识再次进入生产链路的闸门，确保政府政策内容始终可解释、可追责。

最终方向：让官方证据、规则计算、模型分析、用户信号和管理员治理在清晰边界内协作，逐步形成更完整、更及时、更可审计的宝安政策问答能力。
